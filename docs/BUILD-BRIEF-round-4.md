## What changes vs the round-3 build (the delta to implement)
1. **Fonts**: mono switches from IBM Plex Mono to **JetBrains Mono** app-wide (`@expo-google-fonts/jetbrains-mono` — the ONE allowed new dependency; MOBILE-A adds it in `src/ui/fonts.ts`/`tokens.ts`).
2. **Onboarding** gains the prototype's flow: Welcome (logo, tagline, Kai quote, Create account / Log in) → Goal → Risk (cap label bound to balance) → **Personalize** ("Let's tune Kai to you": *How much have you traded?* New to this / Some experience / Trades actively — each with its one-line consequence; *What should Kai watch?* chips big tech · AI & semis · energy · index ETFs · crypto-linked names · earnings plays; summary "Kai will scan X and Y first.") → **Plan** ("Here's how I'll work for you": checklist bound to goal/mode/cap/focus; rows Brokerage (Connect later) · Practice mode (Paper trading on) · Morning briefing (time) → Start with Kai; "Connect a brokerage anytime in Account"). Experience level drives **Kai's voice**: `new` = explains each term the first time (glossary), `some` = plain, skips basics, `pro` = leads with levels and numbers, no preamble. Persist `experience` + `focus[]` (profiles.onboarding.focus + `experience_level`; `explanation_level` follows experience).
3. **Home** = the Kai conversation workspace (round-3 priority object stays as the opening object of *today's* conversation) **plus a conversations drawer** (prototype "Home" board: Search conversations · + New conversation · PINNED · RECENT with titles like "Morning Briefing · Aug 28", "META Day Trade", "Review My Positions"). Conversations get titles, pin, search; the drawer opens from the header.
4. **Ticker page** (`/symbol/[symbol]`) = the research overview from the prototype: header (symbol, company, live price, market state, star), chart w/ 1D/1W/1M/1Y + "Open in Trade →", **Kai's view** card (short take; Ask Kai · Explain the chart · Compare), collapsible sections **Overview** (company summary, Market cap, Next earnings, P/E, Sector), **Technicals** (Trend / Momentum / Volatility meters with qualitative labels; Support / Resistance chips), **Community** (most-mentioned level · posts today · sentiment · "Open META Breakout circle"), and an "A− One active alert · triggered 9:38 · View" row when an alert exists. Round-3's Overview/Kai/Plan/Community tabs move to the Trade Portal (below).
5. **Alerts = complete trade objects** (spec §1–§5): tabs **Active · Watching · History** (rename from Attention/Monitoring; filters for type/mode/delivery — not sections). The **standard alert card**: identity (logo, ticker, company, mode, direction, instrument), oversized **grade medallion** (letter large, 0–100 score small; grade-family border: gold A / violet B+ / violet→graphite B / amber C / neutral unqualified), event headline + what changed + trigger timestamp, company summary (2 sentences max), trade strip (Current w/ freshness · Entry · Stop · Target) + R:R · hold · expires, **qualitative scorecard** (5 mode components with Strong/Confirmed/Healthy/Forming/Waiting/Favorable/Supportive/Neutral + 3–5-segment meters — NEVER fractions like 18/20), one-line Kai interpretation ("Kai's assessment, not a guarantee"), personal fit line (risk $, fits cap, conflicts), community line (secondary), ONE state-driven primary CTA (Watching → *Open chart*; Forming → *Keep watching*; Ready → *Review trade*; Entry reached → *Open Trade Portal*; Planned → *Prepare order*; Order pending → *Manage order*; Position active → *Manage trade*; Invalidated → *See what changed*; Closed → *Review outcome*), expandable detail (full evidence, thesis + scenarios, fit calc, community intel, sources + event history). **No alert-detail page**: `/alert/[id]` becomes a redirect into the Trade Portal with alert context; the inline NL composer stays.
6. **Trade = chart-first Trade Portal** (spec §7), NOT the round-3 landing: `/trade/[symbol]` (and the Trade tab opens the last/priority symbol) with top bar (ticker switcher, live price, market state, paper badge, search, drawers for watchlist · positions · account), dominant chart (1m/5m/15m/1h/4h/D), **Kai annotations** on the chart (trigger, entry, stop, target, support/resistance, note — each with reason + provenance + lifecycle; user can inspect/hide/delete), **context switcher Kai · Alert · Plan · Community** (Kai default) with the working panel under the chart, persistent composer "Ask Kai about this chart…", state-driven execution CTA (→ order ticket). The round-3 landing content (account strip, positions, open orders, watchlist, recents, discovery) moves into the **drawers/sheets**. Kai **chart-control commands** (spec §7): mark the trigger level · switch to daily/5-minute · show what invalidates · mark entry/stop/targets · zoom to trigger candle · compare with prior session · highlight community level · remove/hide/explain an annotation · create/modify an alert from a drawn level · prepare the trade from the plan — the sheet/panel returns `chart_command` frames the client applies in place and narrates.
7. **Opening an alert** routes to the Portal with context restored (spec §6: alert/setup ids, timeframe, trigger candle + timestamp, levels, thesis + grade snapshot, monitoring condition/progress, execution refs, community) and Kai opens with "This is the META alert you opened. I marked the trigger, entry area, stop and first target on the chart."
8. **Community** (prototype boards "Community" + "Setup room"): header "Cheat Code Club · N online"; a **circles row** = time-boxed setup rooms (META · 2d left, CPI · 6h left, NVDA · 4d left, + Create) → the three mode rooms stay as the base (owner decision 2026-08-27: Day Trade · Swing · Investing) and the feed shows the selected room; Kai pinned summary; messages with `$META` chips + reactions + Kai objects ("META A− Ready · Entry 504–507 · Stop 498 · Target 520 · Open setup"); composer "Message Cheat Code Club… $ @Kai". **Setup room** (circle) = "META Breakout · 2 days remaining · 28 members", LIVE chart with levels at the top, thread, Kai verification objects. Circles are `rooms.type='setup'` with `expires_at`; auto-created for ready/A–B setups and closable by the setup's lifecycle. `INCLUDE_SETUP_ROOMS` flips to true. **Owner flag**: the prototype's "+ Create" circle is included as a sheet that creates a circle for a symbol the user chooses (24h/3d/7d) — keep it behind an entitlement flag `circles_create` (premium) so it's real but gated.
9. **Order flow copy for paper** (prototype says "Sent to Robinhood" — there is no broker): Review order = round-3 TR3 with "Stop · paper leg" / "Target · paper leg" rows and the spec's "Broker capability is verified before presenting Submit to broker" (so never that label on paper); **Order confirmed** screen = "Placed · paper account. Buy META · 1 share · limit $X. Stop and target are attached." → View pending order / Done; then accepted → filled distinct (existing).
10. **Account** (prototype board): profile header (name, mode chip, Paper), YOUR KAI PROFILE rows (Trading mode · Experience level · Kai watches — tapping changes them; `cycleMode`/`cycleExp` in the prototype), Kai voice line ("I explain every term the first time it appears."), MY RULES, CONNECTED (none — add a broker later), "You've followed your rules N of the last M sessions · Details" (computed from debrief process receipts; show only when ≥3 sessions exist), Sign out.
11. **Grades**: medallion + scorecard everywhere a grade appears (alert cards, Kai objects, ticker alert row). API provides `score_components[]` as `{key,label,status,strength(0–5),explanation}`; no fractions cross the wire to the UI.

## API-4
- Company profiles: `lib/market/profile.ts` (Polygon reference tickers, cached in instruments.meta, refresh weekly); expose in `/symbols/:symbol` and alert cards.
- `GET /symbols/:symbol` → ticker page payload `{identity, quote, chart_config, kai_view{take, actions}, overview{summary, market_cap, next_earnings, pe, sector}, technicals{trend,momentum,volatility: {status,strength}, support, resistance}, community{...}, active_alert|null, position|null}`.
- `GET /trade/portal/:symbol?alert=&setup=&ctx=` → `{identity, quote, chart_config{timeframe, range, focus_ts}, annotations[], contexts:{kai:{conversation_id, opening_message}, alert: AlertCard|null, plan: {...}, community:{...}}, execution:{state, primary_action}, drawers:{account, positions, open_orders, watchlist, recent}}` — context restoration per spec §6 (opening message text exactly as spec when opened from an alert).
- Annotations: `GET/POST /annotations?symbol=`, `PATCH /annotations/:id` (hide/delete/edit text), Kai-created ones from chart commands.
- Kai chart-control: `POST /kai/conversations/:id/messages` may now emit `chart_command` frames `{command: mark_level|set_timeframe|show_invalidation|mark_plan|zoom_trigger|compare_prior|highlight_community|annotation_remove|annotation_explain|alert_from_level|prepare_trade, payload}` — deterministic where possible (levels come from the setup/alert/plan/community objects, never invented), narrated in text; Kai voice per `experience` (glossary for `new`, terse for `pro`).
- Alerts as trade objects: `GET /alerts?tab=active|watching|history&filter=` returns `AlertCard[]` (full spec §9 contract incl. company_summary, grade, score, score_components qualitative, trade_plan, fit, community, timestamps, state, primary_action); state machine per spec §9 lifecycle (Watching→Active on verified event; Active→Planned when a plan is saved; →Order pending; →Position active; →Invalidated; →History); grade change creates a new version (versioned snapshot). Position events surface as Active cards but management stays in Trade.
- Conversations: `GET /kai/conversations?q=` (titles, pinned, recent), `PATCH /kai/conversations/:id {title?, pinned?}`, auto-title after first exchange (efficient model), "Morning Briefing · <date>" for the daily one.
- Onboarding: `POST /onboarding/complete` accepts `experience: new|some|pro` (map to experience_level beginner/intermediate/advanced) + `focus[]`; Kai system prompt uses both.
- Circles: `GET /circles` (active setup rooms w/ time left, members, last activity), `POST /circles {symbol, ttl}` (entitlement `circles_create`), auto-open circles for ready/A–B setups in the tick, auto-close at expiry (room read-only + History).
- Account: `GET /me` adds `rule_adherence {sessions, followed}` and `kai_profile {mode, experience, focus, voice_line}`; `PUT /settings` accepts experience/focus.
- Smoke: extend for alerts-as-objects (a Watching card promoting to Active on a synthetic tick; grade snapshot versioning), portal payload with alert context, annotations CRUD + a `mark_level` chart_command from a real Kai turn, circles open/expire, conversations list/pin/search, personalize onboarding. Keep green (181 now).
