## The consolidation rules (from the audit; binding)
1. **The symbol is the canonical object.** `/symbol/[symbol]` is the one persistent asset workspace with tabs **Overview · Kai · Plan · Community**. A setup is a *module* inside it, never a separate destination. `/setup/[id]` becomes a redirect to `/symbol/<sym>?tab=overview&setup=<id>` (keep the route for old links).
2. **Kai works in place.** A global Kai **contextual sheet** (V5 W2) opens over the current screen with the screen's context pinned (symbol, setup, alert, order, room). Home remains the full conversation workspace. No Kai action may route the user back to Home.
3. **Home = one priority + one action** (V5 H1): Kai's opening line (what changed, why it matters) → ONE dominant priority object (setup / alert / position / portfolio decision) with ONE primary action whose label is state-driven (Forming → *Watch this*; Approaching/Ready → *Review setup*; Planned → *Buy*; Active → *Manage*; Invalidated → *Review what changed*) → compact "Also watching" rows → composer. The morning briefing detail lives below the fold / in the conversation, not above the priority.
4. **Alerts = Attention · Monitoring · History** (V5 A1) with type filters, NOT five sections; "Active Trades" is gone (positions live in Trade). The Alerts composer accepts natural language ("Tell me when TSLA drops below 170") → preview → activate, inline.
5. **Trade = brokerage hierarchy first** (audit §7): account value + daily change + buying power + PAPER/live status → positions, open orders, items needing action → watchlist + recent symbols → search + discovery → asset detail with price/chart/timeframes → **persistent Buy/Sell** → Kai + community context attached to the asset, not competing with it.
6. **Mode is visible global context** on Home and Trade (chip → sheet to switch, `PUT /mode`), and switching visibly changes briefing, opportunity horizon, default community room, chart timeframe, risk language. Remove per-asset mode "lenses".
7. **Plain-language actions, not taxonomy**: See why · Watch this · Set an alert · Build a plan · Ask Kai · Join discussion · Buy / Sell. Words like lens, object, draft, evidence, fit, monitoring state only appear as secondary detail.
8. **Card saturation down**: strong cards only for actionable/movable objects; metadata rendered on the surface with spacing/typography; dividers and rhythm instead of nested containers; one dominant object + one dominant action per screen; technical depth behind disclosure/sheets.
9. **Preserve the decision chain**: discovery → research → alert → plan → order → position → review stays linked and visible (workspace shows "history" for the symbol).

## Paper execution (new; the T1 / TR3 / P1 arc). PAPER ONLY. No broker, no SnapTrade.
Backend rules from docs/03_SERVICE_SPECS.md Unit 4 + docs/02 §4, simplified for delayed data (Polygon plan = delayed, 5 req/min, no live feed):
- **Preview** (`POST /orders/preview`): freshness gate (quotes are `delayed` w/ `delay_reason:'entitlement'` → allowed, labeled; `stale` → `FRESHNESS_STALE`), entitlement gate (paper allowed on free), risk checks (daily loss cap remaining, max position %, max open positions, min R/R advisory with hard-stop copy), est fill/cost/fees $0, `advisories[]` (dismissible) vs `blockers[]`, `preview_id`, `expires_at` (60s day / 10m swing-invest), `tolerance_bps`, disclosures. Store preview on the `orders` row (`status='previewed'`, `preview` jsonb).
- **Submit** (`POST /orders/submit {preview_id, idempotency_key}`): `PREVIEW_EXPIRED`/`PREVIEW_INVALID` (price moved beyond tolerance vs a fresh snapshot) force re-preview; duplicate key returns original with `deduplicated:true`. Paper fill model: market → fills at last delayed price ± slippage (2bps × spread proxy; partial fills only when qty > 3× a displayed-size proxy — keep simple, document); limit buy fills immediately if limit ≥ last (else stays `accepted`, pending); limit sell mirrors; stop/stop-limit legs become bracket legs. Status flow `draft → previewed → submitted → accepted → (partially_filled)* → filled | cancelled | rejected`; **accepted ≠ filled everywhere**. Bracket = one authorized unit (`bracket_group`): entry + stop + target legs; `exit_style` from plan (`auto` = auto-exit legs, `alert_assisted` = push + one-tap close).
- **Positions**: on fill, upsert `positions` (matching via `side` position_effect exactly), update paper `accounts` cash/buying_power/equity; realized P/L on close; `positions.origin_plan_id/origin_setup_id/origin_room_id` carried from the plan.
- **Mark-to-market + bracket evaluation with no worker**: `POST /internal/paper/tick` (auth: `INTERNAL_SECRET` header) refreshes delayed quotes for all symbols with open positions/pending orders (grouped Polygon call), updates unrealized P/L, fills resting limits whose price is crossed, fires stop/target legs (`auto`) or creates an Attention alert + notification (`alert_assisted`), writes `order_events`/`user_events`. Called by the API itself on a 60s `setInterval` in dev (guarded so only one runs) and documented as a Vercel cron for hosted. Honest copy everywhere: "Paper fills use delayed prices."
- **Plans** (`POST /plans` from `{setup_id}` or manual `{symbol, side, entry, stop, targets, size?}`; `POST /plans/:id/actions activate|cancel|adjust_stop|adjust_target|set_exit_style`): server computes size suggestion from risk policy; scenarios (+$ / −$) and R/R; `plan_events` + `user_events`.
- **Daily risk**: `daily_risk_used` = today's realized losses + open risk (qty × |entry−stop|) on today's positions; day-mode previews blocked (`RISK_LIMIT_DAILY_LOSS`) when cap is spent.
- **Close** (`POST /positions/:id/close` → preview+submit of the opposite side as one convenience) and debrief hand-off (existing `POST /positions/:id/debrief`).
- SCHEMA additions: RPCs `submit_paper_order(...)` (atomic: order status transitions + fills + position upsert + account update + events), `apply_paper_tick(...)` (atomic per position/order), `create_plan(...)`; a `daily_risk` SQL view; every new function ends with the explicit revoke (SCHEMA-NOTES gap 2.7). `orders.preview`, `orders.bracket_group`, `positions.unrealized_pnl` + `mark_price` + `mark_ts` columns if missing.
