# CheatCode trade UI kit

Reusable, data-driven components implementing the approved three-screen concept.
These are TypeScript/React and React Native components, not image slices. The
illustration is a direction reference; SVG charts use the caller's actual bars.

## What's included

| Component | Role |
| --- | --- |
| SetupPreview | Company identity, setup title, candle map, risk/reward and explore action |
| TradeMap | Actual OHLC bars, entry/stop/target lines, selectable level controls |
| RiskRewardRuler | Proportional planned downside/upside; calculates long and short setups |
| KaiAnnotation | Explanation of the selected level; caller supplies actual Kai text |
| TradeStatusStrip | Explicit caller-provided lifecycle state, including expired/invalidated |
| PinnedTradePreview | Compact trade context for a discussion or watchlist |
| ConversationPreview | Avatar, belt identity, reply context and chat messages |
| ConversationComposer (web) | Async send callback; retains draft on failure |
| TradeDetail (native) | Ready-made expanded view with selected-level state and Kai callback |

## Native app

Files: `apps/mobile/src/ui/trade/`. Uses the app's existing `Ticker`, `T`, `Num`,
`KaiOrb`, fonts and tokens. Uses the already-installed `react-native-svg`.
The included Metro change adds `packages/trade-ui` to watch folders.
No dependency or lockfile changes are needed.

```tsx
import { SetupPreview, PinnedTradePreview, ConversationPreview } from '@/ui/trade';
import { TradeDetail } from '@/ui/trade/TradeDetail';

<SetupPreview idea={idea} onExplore={item => openTrade(item.id)} />

<TradeDetail
  idea={idea}
  notes={notesFromKai}
  onAsk={context => openKai(context)}
/>

<PinnedTradePreview idea={idea} onOpen={item => openTrade(item.id)} />
<ConversationPreview messages={messages} composer={existingRoomComposer} />
```

Use the existing room composer/network hooks. The components do not execute
trades, post messages, generate analysis, fetch candles or infer lifecycle status.
Mount inside your existing screen's scroll/safe-area/keyboard containers.

## Website / Next.js

Files: `apps/site/src/components/trade/`. Import from `@/components/trade`.
The native and web public data types and core component props match.
Visit `/component-lab` after running `npm ci` and `npm run dev` in `apps/site`.
The lab shows all three views, level selection, lifecycle states and local chat.
The gallery's chat is explicitly a local demo; it sends nothing externally.

```tsx
import { TradeMap, ConversationComposer } from '@/components/trade';

<TradeMap
  idea={idea}
  selectedLevel={selected}
  onLevelSelect={setSelected}
  annotation={kaiNote}
/>
<ConversationComposer onSend={text => sendRoomMessage(roomId, text)} />
```

Web components use the site's existing CSS tokens and support native keyboard
buttons/focus states. Supply a `logoUrl` from your own existing logo endpoint;
without a URL, the styled ticker remains visible. No invented logo URLs.

## Shared contract and synchronization

`packages/trade-ui/model.ts` is the authoritative geometry, validation, data types
and risk/reward math. `fixtures.ts` is only for the gallery. Do not import fixtures
into live screens or substitute them when an API fails.

The site deploys from its own folder. To preserve that deployment behavior,
`model.generated.ts` and `fixtures.generated.ts` are committed copies generated by:

```
node packages/trade-ui/sync-site.mjs
node packages/trade-ui/sync-site.mjs --check
```

Run these from the repo root after editing the shared model/fixture. Do not edit
the generated files directly. Native imports the authoritative source directly.

## Data mapping

The `TradeIdea` contract is intentionally separate from the backend response.
Your screen adapter must map real setup IDs, symbol, company, OHLC candles,
entry/stop/chosen target, direction, grade and status. Timestamps are milliseconds
since Unix epoch. Choose the target explicitly if the backend returns several.
`dataLabel` should identify source/as-of time or clearly say illustrative data.
Prices default to two decimals; set `pricePrecision` for other instruments.

Never infer `active` from price or set a grade based on a generated chart.
Unknown levels are `null` and display as a dash. Risk/reward is unavailable if
levels are missing or invalid for the direction. Missing OHLC bars show an honest
empty history state with supplied levels only. Invalid bars are removed; duplicate
timestamps use the last provided bar; the chart sorts chronologically and shows
up to 72 recent candles. Near-overlapping chart labels yield to the selected
level; the separate accessible level controls always retain every value.
